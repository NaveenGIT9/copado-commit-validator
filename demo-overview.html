Copado Commit Validator

A VSCode extension that gives developers complete pre-promote visibility before triggering a Copado promotion — catching commit issues, test failures, and promotion conflicts before they cause pipeline failures.
🔍
Commit Intelligence
Every commit on the feature branch not registered in Copado is surfaced with full detail — which metadata components it touches, coverage against the story's metadata list, and author validation
Amended commit detection — when a commit is amended by a different developer, author vs committer mismatch is flagged ✎ amended
Copado auto-commits (sourceApiVersion bumps, PMD rule updates) are automatically identified and exempted from all checks
Verdict calculated per story:
✓ Clean All commits registered in Copado
✓ Covered Unregistered commits, but metadata scope covers them & same author — still eligible to promote
⚠ Needs Verify Covered by metadata scope but committed by a different author — manual review required
✗ Unregistered Commits touch metadata outside the story's scope — blocked
Example — Covered vs Needs Verify
StorySituationVerdict

US-102 Peer dev amended the commit — different committer. Metadata scope matches but author differs. ⚠ Needs Verify
US-103 Commit touches a class not listed in story metadata scope — outside coverage. ✗ Unregistered

Missing test class warning — story has Apex code but no test registered in Copado

Promotion Safety
Completed with errors — flags when the last promotion failed and no new fix commit has been made on the story since. Developer must commit a fix first
In Progress detection — covers both promotion status = In Progress AND when status stays Draft while Copado runs an active SFDX Promote / Deploy job execution
Stuck indicator at 60 min — spinner badge turns red Stuck? so team knows to investigate
Merge conflict — identifies the culprit story vs innocent stories. Innocent stories can still promote separately without being blocked

⚔️
Conflicts Resolved — Smart Handling
All siblings in list — safe to re-trigger old promotion together. Default behavior, no extra steps
Missing siblings detected — warning shown on every story row. Separate promo checkbox is pre-checked so re-trigger is blocked by default
RESOLVED attachment copy — when promoting separately, Copado stores conflict resolution files as attachments named RESOLVED <StoryName> <filepath> on the old promotion. These are automatically copied to the new promotion so Copado skips re-resolution for already-resolved files
Stale resolution guard — attachments are copied only when:
copado__User_Story__c.copado__Latest_Commit_Date__c < copado__Promotion__c.LastModifiedDate
i.e., the developer made no new commits after the conflict was resolved on the promotion. If either date is missing, or the commit date is on or after the promotion's last modified date, the old resolutions may no longer apply — copy is skipped and the checkbox shows: resolutions stale — not copied

Promote Workflow
Stories from the same project and source credential are automatically grouped into a single promotion — no manual effort
Different source credentials → separate promotions created automatically. No silent failures, no cross-environment mixing
Separate promo checkbox per story — override grouping when a story needs its own promotion
Promote list shows story name and developer in aligned columns before confirming
⚡
Release Engineer Experience
Fetch ready stories — pulls eligible stories directly from the Copado list view into the input box with one click
Source → Target environment displayed on each story row so the release engineer always knows which pipeline step each story is on
All checks run in parallel per story — git, Salesforce, and Copado queries happen simultaneously for fast results
Before vs After — What This Replaces
Before (Manual)
✗ Opened each feature branch in Git and manually scrolled through commits — comparing them one by one against the User Story's metadata list in Copado
✗ Checked PR approval status by navigating to each User Story record in Salesforce individually
✗ Manually checked Copado test execution records to find out if Apex tests passed and whether test classes were even added to the test record — no single view across multiple stories
✗ Discovered merge conflicts and In Progress promotions only after triggering — causing pipeline failures and reruns
✗ Re-resolved the same merge conflicts on every new promotion — Copado had no memory of prior resolutions as Smart Conflict Resolution is disabled in our org
After (This Tool)
✓ Every unregistered commit surfaced automatically with metadata coverage verdict — no manual Git browsing
✓ PR approval, test results, and parent story status shown inline for all stories in one view
✓ Merge conflicts, In Progress promotions, and stuck jobs caught before triggering — zero surprise failures
✓ RESOLVED attachments automatically copied to new promotions — conflicts resolved once, not repeatedly
✓ All checks run in parallel — full pre-promote picture for a batch of stories in seconds, not minutes
